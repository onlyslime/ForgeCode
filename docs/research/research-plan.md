# 编程智能体市场调研计划

## 1. 调研目的

为“个人独立设计并实现一个编程智能体”考核建立可辩护的需求依据：识别主流 AI 编程工具的共同能力、差异化能力和实现代价，进而确定一个在截止日前可完成、能在视频中清晰演示、且符合“不得使用现成 agent 框架/SDK”的最小可行范围。

## 2. 题目约束（来自考核 PDF）

- 必须个人独立设计并实现 coding agent；至少能够通过大语言模型读写文件、执行命令完成编程任务。
- 禁止在现成 agent 产品上封装界面；禁止 LangChain、LlamaIndex、OpenAI Agents SDK、Claude Agent SDK、AutoGen、CrewAI 等 agent 框架/SDK。
- 可以使用模型厂商 API 客户端、OpenAI 兼容网关和原生 tool calling；对话历史/上下文、工具定义与本地执行、输出解析、循环终止、错误处理等重要逻辑需自行实现。
- 截止时间为 2026-09-02 24:00（北京时间）；交付公开 Git 仓库、1000 字以内 README.txt、2 分钟以内 MP4 演示视频。
- API key 等凭据必须通过环境变量或未入库配置文件提供，不得进入仓库、README 或视频。

## 3. 调研问题

1. 市面上的工具按产品形态如何分层：终端代理、IDE 原生代理、独立 AI 编辑器、云端软件工程师、传统补全插件？
2. 各产品是否具备文件读写、命令执行、代码搜索、上下文索引、补全/编辑、计划模式、测试与调试、代码审查、Git 操作、MCP/插件、规则/记忆/工作流、并行代理、浏览器/视觉、云端隔离和治理能力？
3. 哪些能力是完成一次可靠“需求→修改→验证”闭环的必要条件，哪些只是提高效率或产品差异化的增强项？
4. 在本题禁止使用现成 agent 框架的前提下，哪些能力值得实现，哪些应明确列为未来路线？
5. 竞品宣传中的“支持”具体意味着什么（只读建议、需用户批准、自动执行、云端托管），如何避免把不同级别的能力混为一谈？

## 4. 产品样本与功能维度

### 重点样本

- 代理/终端：Claude Code、OpenAI Codex、GitHub Copilot cloud agent/CLI、Cline、Aider、OpenCode。
- AI 编辑器/IDE 代理：Cursor、Windsurf（现文档部分迁移至 Devin Desktop/Cascade）、Zed、JetBrains AI Assistant/Junie、Gemini Code Assist。
- 开源可定制助手：Continue。
- 云端软件工程师（作为边界样本）：Devin、Replit Agent。

### 统一功能维度

1. 交互面：CLI、IDE、桌面、Web、移动端、Slack/Issue/PR。
2. 模型与上下文：多模型/BYOK、本地模型、仓库索引、检索、上下文压缩、引用/来源。
3. 工具执行：文件读取/写入/补丁、Shell、代码搜索、LSP、浏览器/截图、外部 API/MCP。
4. 代理控制：Plan/Ask/Act 或 Code 模式、任务循环、工具审批、暂停/继续、队列、重试和回滚。
5. 工程闭环：测试、Lint、构建、调试、依赖安装、Git diff/commit/branch/PR、冲突处理。
6. 协作与复用：规则、AGENTS.md、记忆、Skills、Slash commands、工作流、子代理、并行会话、Worktree。
7. 可靠性与治理：沙箱、权限、网络控制、审计、隐私、遥测、企业 SSO/RBAC。
8. 商业和部署：开源/闭源、云端/本地、订阅/API/免费额度、平台和语言覆盖。

## 5. 证据标准

- 优先使用产品官方文档、官方帮助中心、官方 GitHub README/发布说明；每个关键判断保留可点击 URL。
- 功能只有在官方资料明确描述“可执行/支持”时才记为“有”；“宣传定位”与“实际可执行能力”分开记录。
- 将能力标成“有、部分/需批准、外部集成、未见官方说明”四类，不把未找到资料等同于不支持。
- 定价、版本和可用性变化快，记录调研日期（2026-08-27），不把价格作为核心架构结论。
- 对本题相关性另评分：核心（MVP 闭环必需）、重要（显著提高成功率/可演示性）、锦上添花（复杂或非必要增强）。

## 6. 执行阶段与验收标准

### 阶段 A：资料采集

输出每个产品的定位、交互面、能力证据、限制、来源 URL；至少覆盖 10 个主流样本和 8 个统一功能维度。

### 阶段 B：竞品矩阵

输出“产品 × 功能”矩阵和按产品形态的比较，明确只读/需批准/自动执行/云端托管差异。

### 阶段 C：能力分层

输出核心、重要、锦上添花三级清单，并给出每项对本题的价值、实现复杂度和风险。

### 阶段 D：方案映射

输出一个不依赖 agent SDK 的建议 MVP：模型适配器、对话状态、工具协议与本地执行器、解析器、循环控制、审批/安全、验证器和日志；同时列出暂缓项。

### 阶段 E：报告交付

将结论、矩阵、来源和实施建议补入 `deep-research-report.md`；复核链接、事实表述、中文术语、题目约束和 README/视频需求的一致性。

## 7. 预期结论形式

最终报告不以“功能越多越好”为目标，而是回答：一个可信的个人 coding agent 最小闭环是什么；每个增强能力解决什么问题；在面试中如何解释自主实现、权限边界、失败恢复和验证机制。
